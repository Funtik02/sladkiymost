# Сладкий мост: Якутия ⇄ Донбасс

Маркетплейс кондитерских изделий двух регионов. Конфеты, шоколад, пряники и торты фабрики ЯХК едут из Якутска в Донецк, а вафли, мармелад, печенье и шоколад донецких производителей — в Якутск. Заказы собираются в сборные партии — **волны**: вместе везти дешевле, и чем полнее волна, тем ниже цена доставки для каждого покупателя.

Проект хакатона. Стек: React 18 + Vite + React Router v6 + Context API/useReducer (клиент), Node.js + Express 5 с хранением данных в JSON-файлах (сервер).

## Запуск одной командой

Нужен Node.js 20+.

```bash
npm run dev
```

Команда из корня проекта при первом запуске ставит зависимости в `client/` и `server/`, затем поднимает:

- клиент — http://localhost:5173
- API — http://localhost:3001 (клиент ходит к нему через прокси Vite: `/api` и `/images`)

Другие команды (из корня):

| Команда | Что делает |
|---|---|
| `npm run seed` | Пересоздаёт демо-волны и демо-заказы **относительно сегодняшней даты** (товары и пункты выдачи не трогает) |
| `npm test` | Проверяет, что расчёт доставки на клиенте и на сервере совпадает, и логику закрытия/переноса волн |
| `npm run build` | Production-сборка клиента |
| `npm run lint` | Линтер клиента (oxlint) |
| `npm run images` | Перерисовывает SVG-картинки товаров в `server/public/images` |

## Администратор

Вход: http://localhost:5173/admin. Пароль берётся из переменной окружения `ADMIN_PASSWORD`, по умолчанию — `admin`.

Токен хранится в `sessionStorage` вкладки и живёт 8 часов; после перезапуска сервера нужно войти заново.

- **204817** — подарок с открыткой: его волна не набрала 50 кг и была перенесена, сейчас заказ «в пути»;
- **305522** — заказ на пункте выдачи;
- **411093** — набор «Север + Юг» в подарок, цены скрыты от получателя.

## Логистические правила

- Волна уходит раз в 14 дней в каждом направлении: «Якутия → ДНР» и «ДНР → Якутия». Сервер сам держит в расписании по 4 открытые волны на направление.
- Приём заказов закрывается за 3 дня до отправки.
- Срок доставки — 10–14 дней.
- Партия — от 50 до 300 кг. Заказ, который не помещается в волну, туда не принимается.
- Тариф — 500 ₽ за 1 кг. Скидка за заполненность: больше 50 % (150 кг) — 20 %, больше 80 % (240 кг) — 35 %.
- Термоупаковка — 150 ₽ за заказ.
- Сезон определяется по месяцу **отправки** волны:
  - декабрь–февраль и июнь–август — термоупаковка обязательна для термочувствительных товаров 🌡;
  - май и ноябрь — межсезонье, срок доставки +7 дней;
  - март–апрель и сентябрь–октябрь — ограничений нет, термоупаковка по желанию.

**Формула:** доставка = вес заказа, кг × 500 × (1 − скидка) + термоупаковка (если обязательна или выбрана).
Заполненность для скидки = (текущий вес волны + вес этого заказа) / 300. Суммы округляются до рубля.

Расчёт — чистые функции в `client/src/utils/delivery.js` (мгновенный показ в корзине). Сервер повторяет его в `server/lib/delivery.js` при создании заказа и сумме с клиента не доверяет: цены и вес берутся из базы, а если у сервера вышло дороже, чем видел покупатель, заказ не создаётся и покупатель просит проверить корзину.

## Допущения команды

1. **Пересчёт после закрытия волны.** Покупатель платит по тарифу на момент заказа. После закрытия приёма тариф пересчитывается по итоговой загрузке, разница возвращается — в интерфейсе это фраза «итоговая цена доставки может снизиться, если волна заполнится сильнее».
2. **Перенос волны.** Если к дедлайну волна не набрала 50 кг, она переносится на следующую дату по расписанию (+14 дней). Если на эту дату уже есть открытая волна и вес помещается — заказы переезжают в неё; иначе волна сдвигается сама. Покупатель видит перенос в статусе заказа. Переносит сервер автоматически при наступлении дедлайна, или администратор кнопкой «Перенести».
3. **Срок годности.** Если `shelf_life_days` меньше максимального срока доставки (14 дней, в межсезонье 21) + 7 дней запаса, товар не доедет: показывается предупреждение и добавить его в корзину нельзя. Если товар не успевает только с ближайшей волной (например, ноябрьской), но успевает с более поздней — добавить можно, а неподходящие волны в корзине недоступны.
4. **Одна корзина — одна волна.** В корзине товары только одного направления. Попытка добавить товар другого региона открывает диалог «очистить корзину и добавить».
5. **Набор «Север + Юг».** Собирается на складе в городе назначения: сладости другого региона едут туда встречной волной, местные добавляются на складе. Набор готов к выдаче к прибытию этой волны (по сроку более поздней части набора). В корзине это одна позиция; её направление — в регион назначения.
6. **Закрытие и отправка волн.** При наступлении дедлайна сервер сам закрывает приём (заказы переходят «в сборку»), если набран минимум. Отправку («в пути») выполняет администратор. Дальнейшие статусы заказа администратор меняет вручную, строго по порядку.
7. **Публичное отслеживание.** Страница заказа открывается по номеру, поэтому телефоны и email на ней маскируются, а при опции «не показывать цену получателю» скрываются все суммы.
8. **Оплата картой — имитация.** Это единственная заглушка: данные карты не запрашиваются, через 1,5 секунды «банк» отвечает успехом. Перед имитацией оплаты сервер проверяет и пересчитывает заказ (`POST /api/orders/quote`).

## API

Все ошибки возвращаются в виде `{ "error": "сообщение" }` с соответствующим HTTP-статусом.

| Метод и путь | Назначение |
|---|---|
| `GET /api/products?region=&category=&manufacturer=&minPrice=&maxPrice=&search=&sort=&noTempSensitive=&ids=&limit=` | Каталог; `sort`: `price_asc`, `price_desc`, `popular` (по проданным штукам), `new` |
| `GET /api/products/:id` | Товар или 404 |
| `GET /api/categories?region=` / `GET /api/manufacturers?region=` | Списки для фильтров |
| `GET /api/waves?direction=YKT_DNR\|DNR_YKT` | Открытые волны направления |
| `GET /api/waves/load` | Ближайшие волны обоих направлений (дашборд) |
| `GET /api/pickup-points?direction=` | Пункты выдачи в городе назначения |
| `POST /api/orders/quote` | Проверка и пересчёт заказа без сохранения |
| `POST /api/orders` | Создание заказа → `{ orderId, ...заказ }` |
| `GET /api/orders/:id` | Заказ со статусом, историей статусов и переносами |
| `POST /api/admin/login` → `{ token }`, `POST /api/admin/logout` | Вход и выход администратора |
| `GET/POST /api/admin/products`, `PUT/DELETE /api/admin/products/:id` | Управление товарами |
| `GET/POST /api/admin/waves`, `PUT /api/admin/waves/:id` с `{ action: "close" \| "depart" \| "postpone" }` | Управление волнами |
| `GET /api/admin/orders`, `PATCH /api/admin/orders/:id/status` | Заказы; статус меняется только на следующий |

Админ-маршруты требуют заголовок `Authorization: Bearer <token>`.

## Структура

```
client/                 React-приложение
  src/api/              запросы к API (общий client.js с обработкой ошибок)
  src/context/          корзина (useReducer + localStorage), избранное, админ, уведомления
  src/utils/            delivery.js, season.js, format.js и др. — чистые функции
  src/hooks/            useDebounce, useFetch, useNow, useDebouncedParam, useDocumentTitle
  src/components/       переиспользуемые компоненты
  src/pages/            страницы, в т.ч. pages/admin
  src/styles/           variables.css (все цвета), global/components/pages/admin.css
server/                 Express API
  db.js                 единственная точка работы с JSON-файлами (fs/promises, очередь транзакций)
  lib/                  логика: доставка, сезоны, волны, заказы, товары, авторизация
  routes/               маршруты API
  data/                 products.json, waves.json, orders.json, pickup-points.json
  public/images/        картинки товаров
  scripts/              seed.js, generate-images.js
scripts/                dev.js (запуск одной командой), check-logic.mjs (npm test)
```
